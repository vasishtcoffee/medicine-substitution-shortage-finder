# Short native viva sequence

Follow [setup/execution order and mutation scope](../viva/README.md) first. Use one fresh, dedicated medsub_viva_<suffix> MySQL schema and MongoDB database. Results below are **expected demonstration invariants**, not blanket claims that a future run will pass. Current observed results are in [Testing](TESTING.md).

| Step | Implementation | Native script | How to demonstrate |
|---|---|---|---|
| 1. DDL | [Core tables](../database/migrations/V001__core_schema.sql), [ALTER constraints](../database/migrations/V002__alter_constraints.sql), remaining R__ migrations | [01_ddl.sql](../viva/mysql/01_ddl.sql), [renderer](../viva/prepare_sql.py) | Bootstrap fresh schema/accounts, render existing migrations, SOURCE 01 in mysql or open generated SQL in Workbench. Inspect SHOW CREATE TABLE and SHOW TRIGGERS. |
| 2. DML | medicines and medicine_ingredients in V001; [catalog API](../backend/app/routers/medicines.py) | [02_dml_cascade_rollback.sql](../viva/mysql/02_dml_cascade_rollback.sql) | INSERT a UUID-named medicine/composition, SELECT, UPDATE brand, DELETE parent and show child count 0. ROLLBACK leaves no demonstration records. |
| 3. Queries | [Original joins/nested/correlated/recursive library](../database/sql/queries.sql) | [03_queries_routines.sql](../viva/mysql/03_queries_routines.sql) | Run joins, stock aggregates and recursive category tree. For the original library: python scripts/run_sql_demo.py database/sql/queries.sql, only against the dedicated schema. |
| 4. Procedure/function | [fn_availability_band](../database/migrations/R__10_context_and_guards.sql), [sp_rank_candidates](../database/migrations/R__40_candidates.sql) | [03_queries_routines.sql](../viva/mysql/03_queries_routines.sql) | Show Out/Low/In stock function boundaries; set admin request context, CALL ranking for medicine 1/pharmacy 2, read eligibility and clear context. |
| 5. Triggers | [Inventory low-stock triggers](../database/migrations/R__30_triggers.sql) | [04_triggers.sql](../viva/mysql/04_triggers.sql) | In a transaction insert a new medicine/inventory row, update quantity 50→10→4→40 and read alert counts 0→1→1→0, then rollback. Outbox writes are explicit workflow-procedure calls, not these triggers. |
| 6. CTEs | [Advanced SQL](../database/sql/advanced.sql), category CTE in [medicines API](../backend/app/routers/medicines.py) | [03_queries_routines.sql](../viva/mysql/03_queries_routines.sql) | Explain anchor/recursive member and grouping in the stock CTE; compare results to seeded data. |
| 7. Mongo read/update/delete | [Validators/indexes](../backend/app/mongo.py), [admin feed API](../backend/app/routers/feed.py), [sync](../backend/app/sync.py) | [01_crud.js](../viva/mongodb/01_crud.js) | Set dedicated MONGO_DATABASE, initialize collections, run mongosh URI --file viva/mongodb/01_crud.js. It creates/reads/updates/deletes one UUID event and reads the real inventory_feed collection. Finally removes only its own event. |
| 8. Database permission denial | [Grants](../database/migrations/R__90_grants.sql), [backend context/pools](../backend/app/db.py) | [05_permission_denial.sql](../viva/mysql/05_permission_denial.sql) | Open a separate limited patient-service mysql/Workbench connection. Availability SELECT succeeds; direct inventory SELECT/UPDATE returns SQL permission denial, bypassing HTTP. |

MySQL steps were exercised here, including two direct error-1142 denials. Mongosh was not installed; its script is unverified. Real MongoDB CRUD/validators/indexes/outage recovery were tested separately through pymongo integration tests. No normal/shared server should be stopped to demonstrate outage: run python scripts/check_all.py, whose outage test owns its server.

For UI demonstrations, use [Demo sequence](DEMO_SCRIPT.md). For actual browser coverage and the controller stop, use [Browser verification](BROWSER_VERIFICATION.md). Do not present an expected UI step as an observed result.
