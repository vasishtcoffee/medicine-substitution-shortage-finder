2. Entity classification (15 tables)

KindCountTablesWhy
Strong entities8users, pharmacies, medicine_categories, active_ingredients, medicines, orders, shortage_entries, sync_outboxHave their own primary key and exist independently of any other row.
Weak (existence-dependent) entities4order_items, substitution_reviews, inventory_movements, low_stock_alertsCannot exist without their owner; each is identified through a foreign key to it (identifying relationship): order_items → orders; substitution_reviews → order_items; inventory_movements → inventory; low_stock_alerts → inventory. Implemented with a surrogate id, but the FK is NOT NULL and deleting the owner cascades or is blocked.
Associative entities (relationship tables)3inventory, medicine_ingredients, pharmacist_assignmentsResolve an M:N (or 1:1) relationship and carry its own attributes (e.g. inventory.quantity, medicine_ingredients.strength_mg): inventory = pharmacies M:N medicines; medicine_ingredients = medicines M:N active_ingredients; pharmacist_assignments = users 1:1 pharmacies (pharmacist works at one pharmacy).

sync_outbox is an infrastructure table (transactional outbox for MongoDB) and is classed as strong because it stands alone. schema_migrations (migration bookkeeping) is not part of the model.
